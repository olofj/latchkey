**What I decided**
- **Missing PURPOSE refuses the upload.** The check runs before anything is built and takes about 0.25 s. `UPLOAD=0` and dry runs don't need one; a PURPOSE over 500 characters is always refused.
- **"What changed" counts only commits that change the app itself** (`app/App`, `TSNet`, `ShareExtension`, `ThirdParty`, `Latchkey/`, the Xcode project, `Latchkey.xcconfig`). A commit is linked to a feature by its `Spec:` line, or by a `Fixes #k` that the feature's README row names. A spec landing on its own doesn't count, which is why F25 stays out today: its spec is on main, its code is only on `f25`.
- **Non-feature fixes:** a `Fixes #k` that no feature claims becomes `Fixed: &lt;GitHub issue title&gt;` (fetched with `gh`). Without `gh`, the commit subject is used. Other app changes are only counted ("Plus N internal changes").
- **Things to try** come from each spec's "Device check" heading or bullet, condensed. An item ending in `(owner only)` is left out.
- **Over 4000 characters**, things to try are cut first, then feature lines; the purpose line is never cut.
- **Records:** `make tf` saves the notes to `app/build/testflight-notes/&lt;build&gt;.txt` and next to the `.ipa`. After a successful upload it creates an annotated tag `tf/&lt;build&gt;` whose message is the notes. It then waits up to 30 minutes for processing and sets the notes. If the wait runs out it exits with status 3, and `make tf-notes BUILD=n` sets them later. `make tf-notes DRY=1` prints the notes without changing anything.
